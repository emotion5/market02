**거래명세표 — 인쇄 시 브라우저 머리글/바닥글 제거**
- 거래명세표를 출력하면 미리보기엔 없던 **상단 날짜·문서제목, 하단 사이트 주소**가 찍히던 것을 제거. 브라우저가 자동으로 넣는 인쇄 머리글/바닥글이 그려질 여백을 없애고, 종이 여백은 문서 자체 여백으로 유지.

**배송조회 — 송장 등록 전에는 택배 정보 감춤**
- 결제내역에서 입금대기 때부터 "택배사 / 운송장번호 배송 준비 중"이 보이던 것을, **관리자가 실제 송장을 등록한 뒤(배송중·배송완료)에만** 택배사·운송장번호가 나오도록 변경. 송장 전에는 "아직 송장이 등록되지 않았습니다" 안내와 진행 단계만 표시.
- 조회 버튼 문구도 상황에 맞게 분기 — 송장 전 **"주문 진행상태"**, 송장 후 **"배송조회"**.

**배송조회 — 실시간 조회 실제 연동(라이브 전환)**
- 지금까지 어떤 송장을 넣어도 같은 예시 이력만 뜨던 것을 **실제 택배사 조회로 전환**. 관리자가 목록에서 고른 실제 택배사·운송장 기준으로 진짜 배송 이력을 가져옴.
- 배송조회 서비스는 **deliveryapi.co.kr 를 사용**하기로 결정(비용 효율). 여러 조회사를 교체할 수 있는 구조라, 설정값(`TRACKING_PROVIDER`)만 바꾸면 다른 서비스로도 전환 가능.

**배송완료 — 자동 상태 전환**
- 택배사 조회 결과가 **배송완료로 확인되면 주문 상태를 자동으로 "배송완료"로 전환** — 관리자가 수동으로 누르지 않아도 마이페이지·관리자 뱃지가 맞춰짐. (고객이 배송조회를 한 번 열어보면 반영되며, 안 되면 관리자가 기존 배송완료 처리로 마감)

**사업자 회원 — 세금계산서·견적서용 정보 수집 정비**
- 사업자 가입 시 **담당자명·담당자 연락처**를 추가로 받도록 함(선택). 승인 결과 안내·주문/견적 소통에 사용.
- 사업자 **승인 화면을 "정보 확정" 단계로 전환** — 관리자가 사업자등록증을 보면서 **상호·대표자(세금계산서 필수), 사업장 주소·업태·종목, 담당자, 세금계산서 수신 이메일**을 입력한 뒤 승인. 상호·대표자가 비어 있으면 승인 불가(세금계산서 발행에 필요).
- 지금까지는 대표자 정보를 채우는 경로가 없어 **정상 가입 회원은 세금계산서 발행이 막히던 문제**가 있었는데, 승인 단계에서 확정하도록 해 해소.
- 회원 목록의 대기 사업자 버튼을 **"검토·승인"(상세로 이동)** 으로 변경 — 등록증 확인·정보 입력 없이 즉시 승인되던 것을 막음.
- 세금계산서 발행 시 **승인 때 확정한 수신 이메일**을 우선 사용(없으면 계정 이메일).
- 관리자 회원관리의 등급 버튼 문구를 **"회원도매가 회수" → "회원도매가 적용 취소"** 로 정리(확인창 문구도 일관되게).

**견적서 — 공급받는자에 사업자 정보 자동 표기**
- 견적서 "공급받는 자"란에 상호만 있던 것을, **사업자등록번호·대표자·주소·업태·종목**까지 회원 등록정보에서 자동으로 채워 표기하도록 함. 이 항목들은 등록정보라 **수정 불가(읽기 전용)** 로 보여 상호·대표자와 어긋나지 않게 함.
- 상호도 사업자회원이면 등록정보로 고정 표기(예전엔 입력칸). 담당자·연락처만 견적 건별로 수정 가능.
- 발행 시점에 회원정보를 **그대로 굳혀 저장**하므로, 이후 회원정보가 바뀌어도 지난 견적서는 그대로 보존됨. (공급자란에도 업태/종목 한 줄 추가)
- 개인회원 등 사업자 정보가 없으면 해당 항목은 표시되지 않음.

**주문/결제 — 회원정보 자동 채움 + 주소 검색**
- 로그인한 회원이면 주문서의 **받는 분·연락처·배송지·입금자명·사업자등록번호·상호**를 회원정보로 미리 채워 줌(모두 수정 가능한 기본값). 사업자등록번호·상호 같은 반복 입력·오타를 크게 줄임.
- **배송지에 우편번호 주소 검색**을 붙임(카카오 우편번호). "주소 검색"으로 도로명주소를 고르고 상세주소만 입력 → 잘못된 주소로 인한 배송사고 방지. 사업장 주소가 자동으로 채워지되 **"실제 배송지가 맞는지 확인"** 안내를 함께 노출.

**견적서로 주문 시 — 내용 일치 확인(안전판)**
- 저장한 견적서에서 **"이 견적으로 주문하기"** 로 넘어오면, 주문 화면에서 **그 견적서와 지금 주문 내용이 같은지 자동 대조**해 안내함. 동일하면 "견적서 내용과 동일합니다", 달라졌으면 **수량·단가 변경/제외/추가된 항목**을 짚어 줌. (주문 자체는 견적서와 독립 — 대조만 하는 최소 안전판)

**입금 대기 화면 — 버튼 정렬 교정**
- 주문 완료(입금 대기) 화면의 "확인" 버튼 글자가 위로 치우쳐 보이던 것을 가운데로 정렬.

**배송조회 — 실시간 택배 조회 연동**
- 마이페이지 "배송조회"에서 택배사 실시간 배송 이력(시간·상태·위치)을 보여주도록 함. 기존 진행단계 그림은 그대로 두고 그 아래에 실시간 이력을 덧붙임.
- 국내 종합 택배조회(SweetTracker) 어댑터로 연동(mock/live 전환) — 실키 준비되면 설정만 바꾸면 됨. 관리자 운송장 입력의 택배사는 조회 정확도를 위해 목록에서 선택하도록 변경.

**배송지 관리 — 계정 저장 + 주소검색 + 주문화면 불러오기**
- 배송지 관리가 브라우저에만 저장되던 것을 **계정(DB) 저장**으로 전환 — 다른 기기·재로그인해도 유지.
- 배송지 등록에도 우편번호 주소검색 적용. 주문화면에서 저장된 배송지를 **카드로 골라 불러오기**(기본 배송지 자동 선택). 직접 입력한 배송지는 체크 한 번으로 목록에 저장 가능.

**연락처 입력 — 자동 하이픈**
- 주문·가입·배송지·견적서의 연락처를 3필드 분할 대신 **단일 입력 + 자동 하이픈**(010-0000-0000)으로 통일. 유선번호(02-…)도 자연스럽게 정리.

**증빙 일원화 — 세금계산서/현금영수증 택1**
- 주문 시 증빙을 **세금계산서(사업자) / 현금영수증(개인·소득공제) / 안 받음** 중 하나로만 받도록 정리. 한 주문에 **두 증빙이 동시에 발급되는 일이 원천 차단**됨(이중 증빙 방지).
- 현금영수증도 세금계산서와 같은 격리 어댑터(mock/live)로 발행 구조 마련. 관리자 주문상세에 현금영수증 상태·발행 버튼 추가.
- (배경) 카드결제는 카드매출전표가 증빙이라 별도 발급 불필요, 무통장은 세금계산서·현금영수증 택1 — 업계 표준에 맞춤.

**입금기한 만료 주문 자동 정리**
- 입금기한이 지난 미결제 주문이 계속 "입금대기"로 남던 취약점 보완. 웹훅 유실에 대비해 **주기적 크론 + 고객이 주문목록 열 때 즉석 동기화**로 토스에 재조회해 만료 건을 자동 취소 처리.

**취소 시 증빙 안내 + 발행 시점 조정**
- 발행된 증빙이 있는 주문을 취소할 때 **관리자에게 경고**(수정세금계산서/현금영수증 취소 필요)하고, 주문상세에 경고 배너 표시 — 조용히 어긋나는 것 방지.
- 증빙 발행을 **배송완료 후 발행을 기본**으로 유도(공급시기 원칙에 부합, 배송 전 취소 시 수정 발행 자체가 사라짐). 급한 경우 경고와 함께 "선발행"은 예외 허용.

**상품 상세 모달 — 로딩 후 밀림/확장 교정**
- 상세 모달을 열 때 카테고리명이 늦게 나타나며 상단이 밀리고, 가격 영역이 뒤늦게 늘어나던(회원도매가 줄이 나중에 추가) 문제 수정.
- 카테고리는 상품명 아래 **고정 높이 슬롯**, 가격은 **회원도매가 줄 자리를 항상 예약** → 미리보기·실제 로드 사이 **레이아웃 변화 없이** 처음부터 최종 크기로 열림.

**거래명세표 — 결제내역에서 출력**
- 결제내역 각 주문에 **"거래명세표" 버튼** 추가(결제완료 이후). 해당 주문의 품목·수량·단가·공급가액·세액을 A4 문서로 보여주고 **인쇄/PDF 저장** 가능.
- 공급자 정보(사업장·업태 등)와 함께 **수령자·연락처·배송지**를 표기해 현장에서 누구 주문인지 바로 확인. 세액=반올림(단가×수량×10/110) 등 표준 계산식 적용.
- 세금계산서·현금영수증(적격증빙)과 별개인 **거래 확인용 문서**임을 문서에 명시.

**관리자 로그인 보안 강화**
- **로그인 무차별 대입 방어(레이트리밋)** 추가 — 같은 IP에서 실패가 반복되면 일시 차단. 손님·관리자 로그인 모두 보호되고, 로그인 폭주로 인한 서버 부하도 완화.

**헤더 아이콘 툴팁 — 즉시 표시**
- 헤더 아이콘 설명이 브라우저 기본 툴팁이라 1초 넘게 늦게 뜨던 것을, 마우스 올리면 **바로 뜨는 툴팁**으로 교체.

**홈 첫화면 속도 — 진열 데이터 캐싱**

**상품 옵션 — '옵션 없음(단일 상품)' 처리 (일반 쇼핑몰 방식)**
- 옵션 편집 화면에 **`옵션 없음(단일 가격)` / `옵션으로 판매`** 토글 추가. 옵션이 없는 상품은 **판매가(소비자가·회원도매가)만** 입력하면 되고, 의미 없는 옵션명("기본")을 적을 필요가 없어짐.
- 관리자 상품목록의 옵션칸: 단일 상품은 개수(`1`) 대신 **`단일`**, 옵션 상품은 **`N개`**로 표시.
- 내부적으로는 기존과 동일하게 기본 옵션 1개를 유지(주문·견적이 옵션 단위로 기록되므로). 소비자 화면은 원래부터 단일 상품이면 옵션 선택 없이 수량만 노출 — 변경 없음.

**색상에 이름 붙이기 (일반 쇼핑몰 방식)**
- 상품 색상에 **이름**(예: 블랙, 아이보리)을 지정할 수 있게 함. 관리자 옵션 화면에서 색 견본과 함께 이름을 입력.
- 손님 화면에 색 이름이 표시됨 — **상품 카드·목록**(스와치에 마우스오버 시 이름), **상세 색상 선택**(고른 색 이름을 라벨로 표시), **견적서 담긴 목록**(옵션 옆에 색 이름). 색상은 여전히 옵션과 별개로 선택되며 가격은 없음(표시용).
- 기존에 이름 없이 등록된 색상은 그대로 색 동그라미만 표시(하위호환). DB에 색상 이름 컬럼 추가(비파괴 마이그레이션).

**상품 목록에서 홈 노출 바로 토글**
- 관리자 상품목록 '상태' 다음에 **홈 노출** 컬럼 추가. **노출/비노출**을 클릭하면 그 자리에서 바로 반영(홈 노출 편성 화면에 들어가지 않아도 됨). 켜면 상품이 속한 카테고리 편성 **맨 뒤에 추가**, 끄면 내려감. 순서 조정은 기존 '홈 노출 편성' 화면에서.
- 상태 배지(초록/회색)와 구분되게 파란색 토글로 표시.

**상품 목록 레이아웃·조작 다듬기**
- **상태**도 홈 노출처럼 **즉시 토글**로 변경 → '옵션·상태·홈 노출'은 모두 저장과 무관하게 바로 작동.
- **'저장' 버튼을 가격 오른쪽(옵션 왼쪽)으로 이동** → 저장 대상(왼쪽 편집칸)과 즉시 동작 그룹(옵션·상태·홈노출)이 시각적으로 나뉨.
- 불필요한 '되돌리기' 버튼 제거(저장 전엔 새로고침으로 원복). '상세' 버튼은 **'상품 수정'**으로 이름 변경.

**홈 노출 편성 — '삭제' 표현 개선**
- 편성 목록의 빨간 **'삭제'**가 상품을 지우는 것처럼 오해돼, **'홈노출 제외'**(중립색) + 안내 툴팁으로 변경. 실제 상품은 삭제되지 않고 그 카테고리 편성에서만 빠짐을 분명히 함.

**판매가 관리 개편 — 별도 '대표가' 폐지, 옵션 기준으로 통일 (일반 쇼핑몰 방식)**
- 손으로 따로 입력하던 **'대표가'를 없애고**, 목록·카드 표시가는 **옵션 최저 소비자가로 자동 산출**(옵션 2개↑이면 `12,000원~`처럼 '부터'). 옵션 소비자가와 어긋날 일이 사라짐.
- 상품 수정 화면에서 대표가 입력칸 제거(가격은 옵션에서 관리), 상품 등록의 '대표가'는 **'판매가'**(기본 옵션 가격)로 명칭 변경.

**단일 옵션 상품 — 목록에서 소비자가·회원도매가 바로 수정**
- 옵션이 1개뿐인 상품은 상세로 안 들어가도, 목록의 **소비자가·회원도매가** 칸을 상품명처럼 바로 고쳐 **'저장' 한 번**으로 반영(상품명·카테고리와 함께 서버 트랜잭션으로 원자 저장). 옵션이 여러 개면 그 칸은 읽기전용이고 '옵션'에서 편집.

**상품 목록 레이아웃 폭 정리**
- 컬럼이 많아져 카테고리명이 잘리고 '옵션/단일'이 세로로 쪼개지던 문제 해결 — 상품관리 페이지 폭 확대 + 셀 줄바꿈 금지 + 좁을 때만 가로 스크롤.

**상품 삭제 — 주문 이력 없는 상품만 (안전 삭제)**
- 상품 목록에 **삭제** 버튼 추가(평소 회색, hover 시 빨강, 확인창). **주문 이력이 있는 상품은 삭제 불가**(버튼 비활성 + 안내), 대신 비활성(숨김) 권장 — 마이페이지 구매내역·거래기록이 깨지지 않도록.
- 삭제 시 옵션·색상·이미지·홈편성은 함께 정리되고(주문·견적 문서는 스냅샷이라 영향 없음), 스토리지 이미지 파일도 함께 제거. 서버에서도 이력을 재확인해 우회 삭제를 막음.
